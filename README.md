# DeepONet 2D Wave Equation Experiments

This project implements DeepONet (Deep Operator Networks) for learning surrogate models of 2D wave equation solutions. The architecture is modularized into reusable components and configured via Hydra.

## Quick Start

```bash
# Free evolution (no forcing)
python run_free_evolution.py

# Constant force (with forcing)
python run_constant_force.py
```

## Pipeline Workflow

Each orchestrator script (`run_*.py`) executes:

1. **Data Generation** (optional): Call MATLAB or load existing `.mat`
2. **SVD Analysis**: Compute POD basis, save to `.npy`
3. **Training**:
   - Trunk network: learns spatial-temporal modes
   - Branch network: maps initial conditions to SVD coefficients
   - Optional: Joint DeepONet fine-tuning
4. **Validation**: Generate comprehensive plots comparing predictions vs ground truth

## Configuration System

Hydra manages all hyperparameters via YAML configs. Example structure:

```yaml
# configs/free_evolution/config.yaml
problem: free_evolution
n_modes: 18
n_sensors: 10

trunk:
  hidden_dim: 128
  n_layers: 5

branch:
  hidden_dim: 128
  n_layers: 4

training:
  n_epochs: 500
  batch_size: 512
  learning_rate: 0.001
  train_test_split: 0.8
```

Override parameters via command line:
```bash
python run_free_evolution.py training.n_epochs=1000 n_modes=32
```

## Model Architecture

### Trunk Network
- **Input**: (x, y, t) coordinates ∈ [0,1]³
- **Output**: n_modes spatial-temporal basis functions
- **Normalization**: Outputs normalized to [-1, 1] during training, denormalized to original SVD scale for comparison

### Branch Network
- **Input**: Initial condition sensors (n_sensors × n_sensors grid samples)
- **Output**: n_modes SVD coefficients
- **Normalization**: Inputs and outputs normalized to [-1, 1] during training

### DeepONet Reconstruction
- **Formula**: `u(x,y,t) = Σ trunk(x,y,t) * branch(IC)`
- **Key**: Denormalize trunk modes and branch coefficients separately before multiplication
- This ensures proper scaling of the reconstructed field

## Model Checkpoints

## Validation Metrics

All validation functions report:
- **MSE**: Mean squared error
- **Relative L2 Error**: `||pred - true|| / ||true||`
- **Max Absolute Error**: Element-wise maximum error

## Common Issues

### Old Checkpoints
Pre-refactoring checkpoints may lack 'config' keys. The plotting module handles this by:
- Using `ckpt.get('model_state_dict', ckpt)` fallback
- Inferring dimensions from state dict weight shapes

### Dimension Mismatches
If SVD basis shape doesn't match grid dimensions:
- Extract spatial portion: `U_basis[:Nx*Ny*Nt, :n_modes]`
- Reshape with proper ordering: `order='F'` (Fortran/column-major)

### Scaling Issues
For quantitatively correct DeepONet validation:
- Denormalize trunk and branch outputs **before** multiplication
- Don't denormalize the final product directly
